# 评测引擎（P0-1）实现说明

> 落地日期：2026-10-23 ｜ 对应方案：`docs/competitive-analysis-2026-10-23.md` 的 P0-1
> 一句话：给 PromptStudio 装一把尺子——改完 prompt 跑一遍用例，用断言判定"是不是真的变好了"。

---

## 1. 它解决什么问题

在这之前，PromptStudio 的闭环是「AI 改 → 人看 diff → 接受」。问题是**"看"没有标准**：改了 12 处，哪一处真的提升了质量？换了个模型，效果掉了还是涨了？没人说得清。

评测引擎把这件事变成可复现的证据：

```
模板（当前 doc 或打开的文件）
   ├─ {{变量}} 按用例渲染
   ├─ 按用例输入调用模型
   └─ 逐条断言判定 → 通过/失败 + 原因
```

结果落库（Dexie `evalRuns`），可回看历史运行。**这是后续做 Agent 的前置依赖**——没有 `run_eval`，Agent 无法判断自己改得对不对。

---

## 2. 界面

入口：左侧导航「提示词评测」或顶栏「评测」Tab。

三栏结构：

| 栏 | 内容 |
|---|---|
| 用例 | 用例列表（新建 / 复制 / 删除），显示变量数与断言数 |
| 用例详情 | 名称、用户输入、变量（自动检测模板里的 `{{var}}`）、断言列表 |
| 评测结果 | 汇总（通过数 / 平均耗时 / tokens / 成本）+ 结果矩阵 + 历史运行 |

结果矩阵：行 = 用例，列 = 断言位置，点击行展开「模型输出全文 + 每条断言的判定理由 + 耗时/tokens/成本」。

各用例断言数量不同时，表头退化为「断言 1/2/3」——悬停单元格可看该位置实际的断言类型与判定详情。

---

## 3. 配置格式

支持 YAML 与 JSON（YAML 是 JSON 的超集，同一套解析器）。导入即替换当前用例集。

```yaml
promptRole: system          # system = 提示词作为角色设定；user = 作为任务模板
cases:
  - name: 明确结论 + 禁止模糊词
    input: 退款多久到账？
    vars:                    # 可选，替换模板里的 {{var}}
      topic: 退款
    assert:
      - contains: 工作日
      - not-contains: 大概
      - regex: "^结论[:：]"
      - max-latency: 20000
      - llm-rubric:
          value: 先给结论，再给依据；不得使用模糊限定词
          threshold: 0.7
```

写法糖：`- contains: 工作日` 等价于 `- { type: contains, value: 工作日 }`；`assert` / `asserts` / 测试用例常用 `tests` 键都接受。

## 4. 断言类型

| 类型 | 判定 | 取值 |
|---|---|---|
| `contains` | 输出包含该文本 | 任意字符串 |
| `not-contains` | 输出不含该文本 | 任意字符串 |
| `regex` | 正则命中（`m` 模式） | JS 正则，如 `^结论[:：]` |
| `equals` | 去首尾空白后完全相等 | 期望文本 |
| `json-valid` | 能解析出 JSON，且指定字段路径存在 | 逗号分隔路径，如 `answer,tags.0` |
| `max-latency` | 本次调用耗时不超过阈值 | 毫秒 |
| `llm-rubric` | 模型按评分标准打 0-1 分，≥ 阈值通过 | 评分标准 + threshold（默认 0.7） |

前 6 类是确定性的（不额外花钱、不抖动）；`llm-rubric` 需要额外一次模型调用，评分结果与理由都会写进明细。

**通过口径**：一条用例的所有断言都通过才算通过；未配置断言的用例只校验"模型是否正常返回"，不因缺断言判失败。

## 8. 回归基线（P1-2）

> 一句话：把「这次评测」钉到具体版本上，版本时间线直接看分数涨跌，退化的用例能点到那一处 changeBlock。

### 8.1 数据与口径

| 项 | 口径 |
|---|---|
| 运行记录 | `EvalRun` 新增 `versionId` / `versionLabel` / `versionNumber` / `score`；Dexie 升到 **v5**，`evalRuns` 加 `versionId` 索引（旧数据不丢，字段缺省按未版本化处理） |
| 版本绑定 | 手动指定版本 > 主文档内容与最新版本完全一致 > 未版本化；文件模式下不绑主文档版本 |
| 分数 | 通过用例数 / 总用例数 × 100，沿用「全部断言通过才算用例通过」的旧口径 |
| 版本曲线 | 每个版本取最近一次运行；只出现在有运行的版本（没跑过就是「未评测」）；未版本化运行单独排在最后 |
| 基线选择 | 优先「上一个有评测记录的版本」；没有则取当前运行之前最近的一次运行 |
| 用例匹配 | 先按 `caseId`，匹配不上退回 `caseName`，再退回内容指纹（见 §8.6） |

### 8.2 退化定位（启发式）

`locateRegression` 只把「最可疑的 changeBlock」排出来，并强制展示命中依据，不假装是精确归因：

| 信号 | 权重 |
|---|---|
| `contains` 失败，变更把该字面量从提示词里删掉 | +4 |
| `not-contains` 失败，变更把该字面量加进提示词 | +4 |
| `not-contains` 失败，变更删掉了禁止性表述（禁止/不得/避免…） | +3 |
| 字面量出现在变更片段中 | +1 |
| 字面量只出现在变更说明里 | +1 |
| 用例输入里的词命中变更片段 | 最多 +2 |

- 同一断言只取最长命中词（「工作日 / 工作 / 作日」只算一次），避免重复抬分。
- `accepted === false` 的变更块不参与定位（被拒绝的修改没进版本内容）。
- 无命中时如实显示「没有找到相关改动」，而不是硬给一个块。

### 8.4 为什么这样设计

- **分数只按通过率**：断言数不同的用例不按断言加权——否则一条配了 8 个断言的用例会淹没其他用例，口径也不直观。
- **曲线每个版本取最近一次**：同一版本反复重跑时，用户想看的是「这版现在什么水平」，历史最好成绩只放在 tooltip 里。
- **定位给依据而不是结论**：`changeBlock` 是文本级修改，和「模型为什么没答对」之间没有确定性映射；把命中的字面量、删除的禁止性表述展示出来，用户才能自己判断。
- **目标版本只对本次运行生效**：跑完自动清空，避免下次改了内容还误以为在评测当前文档。

### 8.5 已知边界

| 边界 | 现状 | 下一步 |
|---|---|---|
| 跨模型混在一条曲线 | 曲线取最近一次运行，可能来自不同模型（tooltip 里有模型名） | 需要时按模型分线 |
| 用例集变化 | 已改为快照 + 共同用例口径（§8.6）；旧运行（无快照）仍按名称匹配 | 锁定用例集版本后重新计算历史分数 |
| 定位准确率 | 依赖字面量重合，纯语义相关的改动可能定位不到 | 可接一次轻量模型做归因（额外计费） |
| 自动建立基线 | 需要已配置 Key 才能跑历史版本 | 云化后可在版本创建时自动跑基线 |

### 8.6 用例集快照（P1-2b）

> 问题：用例集可以随时改，改完再跑，「100 分 → 75 分」可能只是少测了两条用例。

#### 存了什么

`EvalRun` 新增两个字段：

| 字段 | 内容 |
|---|---|
| `dataset` | 开跑瞬间冻结的 `EvalCase[]` 深拷贝（含 input / vars / asserts / threshold） |
| `datasetHash` | 用例集指纹（8 位十六进制） |

指纹口径（`src/lib/eval/dataset.ts`）：

- 只看「测什么」：输入、变量（键排序）、断言（类型/值/rubric 阈值，未填阈值按 0.7）；
- **不看** id、名称、描述——重新导入或改名不应被当成新用例集；
- 整组指纹**与顺序无关**（顺序只影响结果矩阵排版）；
- FNV-1a 32 位同步哈希，本地比对够用，不作为安全哈希。

开跑时冻结快照还有一个作用：运行中继续编辑用例，不会污染这次结果。

#### 比较口径

| 场景 | 行为 |
|---|---|
| 指纹一致 | 按原来的整体分数算涨跌 |
| 指纹不同，但两次都有快照 | 涨跌改为「共同用例」口径：只统计两次都有、且内容未变的用例；新增/移除/修改的用例不计入 |
| 同一条用例内容改过（输入/变量/断言） | 标为 `changed`（「改动」），不当作修复/退化，不参与共同口径 |
| 只改了用例名 | 不算用例集变化（名称不参与指纹），仍按通过/失败比较 |
| 旧运行没有快照 | 退回 `caseId → caseName` 匹配（旧口径），面板标「旧运行未存快照」 |

面板上会同时给出两组数：

```
回归基线                                  共同 -33
用例集 edc786a4 → a246fbbd  已变化   [载入本次用例集]
v2 100 分  →  v3 80 分
用例集已变化：新增 1 · 移除 0 · 修改 1。涨跌只看共同 3 条用例（100 → 67 分）；
整体 100 → 80 分仅供参考。
```

#### 可复现

「载入本次用例集」把运行快照写回编辑器（先确认，不静默替换），这样历史基线可以原样重跑；变更定位也优先用运行快照里的断言定义，用例后来被改过也能对上当时的字面量。

#### 验证

新增 14 项单测：指纹与顺序/命名无关、输入/断言/变量会改指纹、rubric 默认阈值口径、共同用例分数、changed 识别与修改字段、旧运行降级。
浏览器新增 13 项：同一套用例标「一致」→ 改过用例集标「已变化」、`共同 -33`、新增/修改提示、改动行、载入快照后用例集变为 5 条；以及结果栏滚动回归（回归基线卡片不被 flex 压缩、可滚到底）。
